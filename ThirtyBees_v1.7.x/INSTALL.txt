====================================================
PlugnPay Remote API Module (Credit Card Payments)
Payment Module for thirty bees v1.7.x — module v1.0.1
====================================================

***** IMPORTANT NOTES *****
This module is provided "AS IS". Limited technical support assistance
will be given to help diagnose/address problems with this module.

This module requires SSL and PHP cURL. thirty bees collects credit card
information on your store's billing pages. Authorization is performed
via PlugnPay's Remote API (authonly or authpostauth). Capture, void,
and refund are performed in PlugnPay Merchant Admin — not from thirty bees.

PCI: Collecting cards onsite increases PCI scope. For hosted (lower
PCI) checkout, use PlugnPay Smart Screens v2 (see INSTALL_SS2.txt).
***************************

To Install:

1. Preferred: In Back Office → Modules and Services →
   "Upload a module", upload thirtybees_1.7.0_api_module.zip.

   Or unzip thirtybees_1.7.0_api_module.zip into your thirty bees
   modules directory so you have:
     modules/plugnpayapi/...

   From this repo's development tree that is:
     ThirtyBees_v1.7.x/src/modules/plugnpayapi/ → <shop>/modules/plugnpayapi/

2. In Back Office → Modules and Services, install/enable
   "PlugnPay Remote API".

3. Configure Publisher Name + Remote Client Password. Choose Authorization
   Type (authonly or authpostauth). Select allowed currencies under
   Payment preferences / module currency restrictions.

Requirements:

- thirty bees 1.7.0
- PHP 8.0 or later with cURL and OpenSSL
- HTTPS enabled for the storefront
- PlugnPay publisher name
- PlugnPay Remote Client Password (not the Merchant Admin password)

SSL and checkout redirect loops:

If checkout pages such as order?step=1 fail to load or the browser
reports "too many redirects" after enabling SSL:

1. In Preferences → SEO & URLs, set the SSL shop domain to the same
   host as your storefront, using https://.
2. Ensure PHP can detect HTTPS. Behind Apache or a reverse proxy,
   pass HTTPS=on or X-Forwarded-Proto: https to PHP.
3. Do not enable "Enable SSL on all pages" until both steps above
   are correct.
